D1·1x01 — 2026-09-15
rule: Hot-path event and projection behaviour is defined by docs/SPEC.md plus the conformance suite and must pass against both the TypeScript and Rust implementations; Rust schema types are generated from packages/schema/src, never hand-written.
chose: Adopt Rust for sofar's HOT PATH, incrementally, starting now. Ruled by the run owner 2026-09-15 ("yes do it").
SUPERSEDES, for the hot path only, the CLAUDE.md engineering conventions:
- "TypeScript strict mode; Node ≥18; ES modules";
- "Dependencies: … Nothing else without logging a Decision". Rust crates are limited to serde, serde_json and ulid until another Decision adds one.

Scope of `sofar-core`: hook handlers (session-start, user-prompt-submit, post-tool-use, stop, session-end), atomic event append, fold, digest/status render, and statusline.

TypeScript keeps: the MCP server, `sofar drive`, init/doctor/review, and cloud commands.

The contract comes first: docs/SPEC.md plus a black-box conformance suite over commands, hook stdin/stdout, env and record bytes. It runs against BOTH implementations.

The schema rail holds: event payload types stay authored ONLY in packages/schema/src. Rust types are GENERATED from them, never hand-written. Projection templates keep one source of truth, and Rust output is verified byte-identical by golden tests.

Parity gate: 100% conformance, perf targets met, and a benchmark arm "sofar-rust-core" vs "sofar-ts" that shrinks no D19 lead margin.

Sequencing: r1-fixes waves 1–2 land in TypeScript now, and the Rust core must reach parity INCLUDING them. After parity, new hot-path code is Rust-only, which stops the TypeScript port surface growing. Distribution: prebuilt per-platform binaries through npm optionalDependencies, with a TypeScript fallback.
over: 
- A big-bang rewrite now: it freezes waves 1–3, leaves round 2 unable to attribute gains, and means porting 27.6k engine lines and 34k test lines before anything is trustworthy.
- Staying TypeScript-only behind a measure-first gate: the run owner's point is that the port cost grows with every feature, and Codex CLI, Turborepo and Biome show the path is proven.
because: 
- Sofar runs on every tool call of every agent session. A native core gives near-zero hook start-up, fast folds over very large records (this repo's own is 9.7 MB), a single binary with no Node dependency for Codex/Cursor/OpenCode users, and headroom for many parallel agents.
- Measured 0.31 hooks are only ~0.75% of session time today, so the win is future scale and distribution rather than today's tokens. That is why it goes incrementally, and must pass the same benchmark gate as any other change.
- A conformance-first strangler port means neither implementation can drift from the SPEC.

chose: Byte parity is defined against the TypeScript engine's JavaScript text semantics, inventoried in docs/HOTPATH.md §Text-semantics pins: lengths and clips in UTF-16 code units, JS non-unicode regex classes, JS whitespace class, ECMAScript number formatting in canonical JSON, Node path.relative/basename, Math.round half-up, millisecond ISO timestamps. docs/HOTPATH.md is the hand-written contract inventory the conformance suite (1.2) drives; SPEC gaps it lists (G1–G15) are resolved by SPEC edits or Decisions, never by letting the two implementations differ.
over: Rust-native defaults (char/byte lengths, Unicode-aware regex classes, ryu number formatting) with SPEC amended to tolerate the drift between implementations.
