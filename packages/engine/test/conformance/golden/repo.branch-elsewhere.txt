M2 — 2026-08-30
Capturing a headless agent's real stream shapes costs nothing: point it at an unreachable provider and read what it emits before the network fails. For codex — `codex exec --json --ephemeral -c 'model_providers.fake={name="fake",base_url="http://127.0.0.1:9/v1",wire_api="responses",request_max_retries=0,stream_max_retries=0}' -c model_provider=fake "probe"` — yields thread.started, turn.started, error and turn.failed, and proves every other flag on the command line parses. Use it to verify an adapter's argv and parser against the real binary instead of writing them from memory; only the success-path shapes (turn.completed) need a model, and those can be read from the binary's structs and from a real rollout file in ~/.codex/sessions/.

M4 — 2026-08-30
After a publish, `npm install -g --prefix ~/.local sofar.sh@latest` can silently NO-OP — observed 2026-08-30 right after 0.30.0 shipped: the command exited 0, printed nothing under --silent, and left the global at 0.29.0; the same command pinned as `sofar.sh@0.30.0` changed 1 package and landed 0.30.0. npm's registry metadata was already fresh (`npm view sofar.sh dist-tags` said latest 0.30.0), so the stale resolution is npm's own packument cache, not the registry. Always PIN the version when upgrading the global, then verify with `sofar --version` — an unverified `@latest` reproduces exactly the failure the global-upgrade rule exists to prevent (hooks dogfooding a stale engine for days). Also seen in the same release: a publish interrupted by the web auth round-trip stages the version, so the retry fails E409 "Cannot publish over previously staged version" even though the FIRST PUT succeeded — check `npm view <pkg> dist-tags` and compare `dist.shasum` against the local `npm pack --dry-run` before assuming the release failed.
