D1·jg2y — 2026-09-15
rule: Never put a decimal string or float money value in an API request or response — always {amount_minor, currency} integer minor units.
chose: Money in the API is always {"amount_minor": integer, "currency": "ISO code"} in the currency's minor units (JPY/VND exponent 0, JOD 3), in both request and response bodies

D5·y43y — 2026-09-15
rule: Never hard-DELETE a traveller-made row or ask for delete confirmation — soft-delete through softDelete() in apps/web/lib/deletions.ts, and filter `deleted_at is null` in every list, total and suggestion.
chose: App-wide soft delete: every traveller-made table has a nullable `deleted_at`; deleting stamps it AND appends a row to a `deletions` log (seq autoincrement, entity, entity_id, deleted_at, undone_at), both in one transaction, via `softDelete()` in apps/web/lib/deletions.ts. POST /api/undo takes the highest-seq un-undone log row, clears the entity's `deleted_at`, stamps `undone_at` and returns { restored: { entity, id, item } }; with none it is 409 `nothing_to_undo`. Repeated undo walks back through older deletions (a stack). Every list/total/suggestion/lookup query filters `deleted_at is null`; PATCH/DELETE on a deleted row is 404.
over: Hard DELETE with a confirm dialog; a per-feature trash table; ordering undo by deleted_at timestamp
because: The traveller decided: nothing they made is ever hard-deleted and nothing asks "are you sure?". One log across all entities makes "the most recent deletion" well defined app-wide. Ordering is by log seq, not timestamp, because BOOPADA_NOW freezes the clock so every deletion in a test shares one timestamp. Future entities (trips, days, to-dos) register their table in SOFT_DELETABLE and a reader in lib/undo.ts; a cascading delete should log ONE row for the parent and stamp children with the same deleted_at so undo restores the whole group.

M1 — 2026-09-15
Provider gotcha: `providers.fx.getRates(base)` omits `base` itself from `rates` (its rate would be 1). The set of currencies the providers know is `{rates.base} ∪ keys(rates.rates)` — ten of them: AED EUR GBP INR JOD JPY NZD SGD USD VND. Take it from `apps/web/lib/reference.ts` (`getReference()`), never straight from `rates.rates`, or USD — the default home currency — fails its own validation.
