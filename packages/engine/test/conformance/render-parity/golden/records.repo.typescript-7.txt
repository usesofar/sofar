because: The upgrade is provably invisible to everything sofar ships. tsc is used in exactly two places — noEmit typechecking and the L2 declaration emit in build.mjs — and never touches the esbuild bundles that are the actual published artifact, so all three JS bundles plus every runtime file hashed identical. The only delta is cosmetic: TS 7 preserves the source quote style in emitted string-literal types, so three d.ts files render readonly ['pass', 'findings'] where TS 6 rendered readonly ["pass", "findings"]. Those are the same type; no consumer can observe the difference. The config was already on the favorable side of the port — ES2022, ESNext, Bundler resolution, strict, noUncheckedIndexedAccess, isolatedModules, skipLibCheck, nothing legacy for the native compiler to reject. One behavioural difference found and worth knowing: TS 7 enforces forceConsistentCasingInFileNames against the invocation path where TS 6 normalised it away, so running tsc through a differently-cased path than the repo's canonical one (/Users/jins/io vs /Users/jins/IO on a case-insensitive macOS volume) raises TS1149 on files reached by relative import rather than through the workspace symlink. That is an invocation-path artifact, not a code defect: npm run typecheck runs from the package directory and is clean. Note the speedup is build- and editor-time only — it does nothing for the 26ms CLI hot path, which is Node executing esbuild output.

M1 — 2026-08-29
Record-hygiene D1 exempts a Bash call only when EVERY shell segment leads with git or sofar. Decorating a git command with echo labels — the common `echo "=== status ===" && git status` habit — breaks the exemption, so the PostToolUse hook appends a command_run event and the tree is dirty again the instant it was clean. This is exactly the loop D1 was written to break, and it is easy to re-enter by accident right after a write-back, where the trailing event lands after session_ended and forces an amend. Convention: once you have written back, run git and sofar commands BARE and chained only to each other (`git add <paths> && git commit --amend --no-edit`), with no echo, no comments and no pipes to head. Use echo decoration freely before the write-back, never after it.
