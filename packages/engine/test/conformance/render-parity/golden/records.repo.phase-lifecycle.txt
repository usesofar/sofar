D1·yp20 — 2026-08-13
rule: Phase and task-structure writes are MCP-only — never add a CLI writer for them; the convention dialect uses `sofar event append`.
chose: Phase status gets an MCP tool ONLY — no `sofar phase` CLI sibling. The MCP-less convention dialect keeps reaching phase_status_changed through `sofar event append`, exactly as it already reaches task_status_changed, so no caller is stranded.
over: (a) A CLI command alongside the MCP tool, mirroring `close` and `remember` which are both dual-path. (b) CLI-only, keeping every plan-structure write in the convention dialect.
because: Measured this session on the installed binary (N=15, mean): `sofar event append` costs 61.5ms, of which 50.5ms is process spawn plus full-bundle parse and only ~11ms is the actual record work; an MCP call on the already-running server costs that ~11ms alone. The CLI path also spawns a SECOND process, because the PostToolUse matcher is Edit|Write|MultiEdit|Bash and never matches mcp__sofar__*, so every Bash-issued sofar command fires a hook that reads the command, applies the record-hygiene D1 self-recording exemption and appends nothing. End to end that is ~92ms across 2 processes against ~11ms across 0 — roughly 8x. Correctness decides it independently of speed: `sofar event append` resolves by branch alone and never consults the session home (record-integrity M1, and AppendArgs.slug documents it), so on this shared worktree, where peers rebind branches mid-session, the CLI path can misroute the write that this initiative exists to make reliable. Precedent agrees — task status has no CLI writer either. The existing dual-path commands are dual because they touch bindings.json or the git branch, which an MCP call cannot sensibly do; phase status touches nothing outside the log. Benchmark: scratchpad/bench-paths.sh.

1.
