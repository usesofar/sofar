M2 — 2026-08-05
Committing the record cleanly requires the git call to be BARE. The record-hygiene D1 exemption (packages/engine/src/cli/event.ts, shellSegments + SELF_RECORDING_COMMANDS) splits a command at every shell separator INCLUDING NEWLINES, and exempts it only if EVERY segment leads with `git` or `sofar`. So `git add -A && git commit -F msg.txt` is exempt, but a heredoc (`git commit -F - <<'EOF' … EOF`) is not — the message body's own lines are scanned as segments and lead with ordinary prose words. Mixing in `echo`, `printf`, or any non-git segment defeats it the same way. Symptom: you write back, commit, and the tree is dirty again with command_run events describing the commit itself — the exact non-convergence D1 exists to prevent. Fix: put the commit message in a file and use `git commit -F <path>`, and run status/diff checks as bare git calls, not compounded with echo.
